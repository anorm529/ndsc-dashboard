# NDSC Dashboard

Next.js App Router dashboard for NDSC matchday data and Neon Postgres admin workflows.

## Local Setup

1. Install dependencies:

```bash
npm install
```

2. Create `.env.local` from `.env.local.example` and set:

```bash
DATABASE_URL="postgresql://..."
```

Use the pooled Neon connection string for normal app queries. Do not prefix database variables with `NEXT_PUBLIC_`.

3. Run locally:

```bash
npm run dev
```

4. Open:

```text
http://localhost:3000
http://localhost:3000/members/admin/database
```

## Environment Variables

- `DATABASE_URL`: required Neon/Postgres connection string.
- `NEON_DATABASE_URL`: optional fallback name for the same connection.
- `ADMIN_UPLOAD_SECRET`: reserved for adding extra upload protection.
- `APPS_SCRIPT_URL`: optional legacy fallback for the existing dashboard API if Neon is not available.

## Neon Objects Expected

The admin area is schema-aware, but it expects these public tables/views to exist for full functionality:

- `seasons`
- `teams`
- `team_seasons`
- `players`
- `player_team_seasons`
- `games`
- `player_game_stats`
- `player_season_stats`
- `player_season_stats_archive`
- `awards`
- `league_standings`
- `upload_batches`
- `upload_errors`
- `v_player_game_stats`
- `v_player_season_totals`
- `v_player_season_stats`
- `v_team_fixtures_results`
- `v_ndsc_calendar`
- `v_league_standings`

The EOS actions call these database functions when present:

```sql
select refresh_player_season_stats();
select refresh_player_season_stats(2026);
select refresh_player_season_stats(2026, 'barracudas');
select archive_player_season_stats(2026, 'admin');
```

## Admin Uploads

CSV uploads are available at `/members/admin/uploads` for players, game stats, league standings and fixtures/results.

CSV headers are normalized to snake_case and matched to live table columns. Uploads run inside a transaction, insert valid rows, and write summary/error records to `upload_batches` and `upload_errors` when those tables are available.

Calculated rate stats such as AVG, OBP, SLG and OPS should remain generated by Postgres from raw stat fields rather than imported as source-of-truth values.
